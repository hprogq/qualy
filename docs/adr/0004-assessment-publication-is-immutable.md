# ADR 0004:正式公示永远是不可变快照

- 状态:**已接受**(2026-08-08)
- 领域:综合素质测评(docs/assessment-design.md §7 ADR-1)
- 相关:[ADR 0005](0005-review-escalation-is-not-appeal.md)

## 背景

政策规定每学期两次公示:3 月/9 月第一次公示,学生三个工作日内提异议,工作小组三个工作日内答复,
自第一次公示起六个工作日内第二次公示。学生的申诉句式必然是「我对**第一次公示里的这一行**有异议」。

综测成绩是奖学金、评优、推免与就业推荐的依据,分数错一位小数都会引发真实争议。

## 决定

系统只有两类成绩,类型不同、生命周期不同,**不得合并**:

- **实时预览(provisional)**:随审核通过、材料撤回、评分录入、申诉更正不断变化;学生随时可看,
  永远是「现在算出来是多少」。
- **正式公示(released, immutable)**:`Publication` + `PublicationRow` 一经 PUBLISHED 不可修改。
  第二次公示是**新的** Publication,吸收更正后的新 ScoreRun;**S1 永不原地改成 S2**。

配套约束:

- 只有完整、通过 preflight、由 READY 的 ScoreRun 支撑的快照才可进入 SCHEDULED。
- SCHEDULED 存续期间,一切影响该快照输入的写操作被拒绝(错误码 `PUBLICATION_SCHEDULED_FROZEN`),
  要改先取消预告。**已向学生承诺 9:00 公布,就不允许 9:00 因后台复检失败而不公布**——复检发生在
  SCHEDULED 之前,发布本身是纯机械动作。
- `publish_at`(对学生承诺的时刻)与 `published_at`(调度实际执行时刻)分离;调度晚几十秒
  **不移动**申诉截止。
- `publication_rows` 在 READY 时从 ScoreRun 物化并自包含,正式公示页不再实时调计分引擎。

## 后果

- 「动态正式公示」不存在,也不会在任何触发条件下出现。
- 归档后几年重新打印,看到的仍是当年的 Revision、审核事件与 S2,不重算当前库。
- 管理员能逐句解释「第一次 83.25 → 申诉更正 +1 → 第二次 84.25」,这是砍申诉量最有效的投资。
