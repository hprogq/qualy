# ADR 0009:第一次公示后评分语义冻结,纠错走公示撤回

- 状态:**已接受**(2026-08-09)
- 领域:综合素质测评(docs/assessment-design.md §9、§17、§32.18)
- 前提:[ADR 0004](0004-assessment-publication-is-immutable.md)

## 背景

配置生命周期允许 active 批次自由编辑(带审计),而 S1 与 S2 之间没有 SCHEDULED 时按原规则
仍是"自由编辑"。于是可能发生:S1 公示后没人申诉某题,管理员把该题 +1 改成 +2,S2 全员按新
规则出分——这不再是"S2 吸收申诉结果",而是"S2 用了一套新政策",且变化发生在申诉窗之后,
学生对新规则没有任何申诉机会。

## 决定

**第一次公示(preliminary)发布之后,任何影响全体学生评分语义的修改——calculator、
aggregator、ScoreGroup(cap/floor/结构)、题目计分配置、参与者集合——必须重新产生一次
可申诉的 preliminary release,不得经普通编辑进入 S2。**

S1 后仍然合法变化的只有:申诉/复查轮的裁决、既有事实的状态变化、行政认定条目的录入
(进 S2 前经 preflight 显式确认)、装饰性文本(审计)。

逃生舱是公示撤回而不是修改:`Publication` 状态增加 `RETRACTED`。
`retractPreliminary(reason)` → S1 内容永久保留并标记"已撤回" → 回到公示准备流程 →
修改规则 → 重新 ScoreRun → 发布新的 preliminary → 重新开启申诉窗。**不修改 S1,
也不把错误偷偷带进 S2。**

机械咬合两条:撤回时当前申诉期落下结束边界(actual 照记,历史不改写),插入新的公示创建期,
被撤回公示在时间线保留标记;在途申诉轮继续走(锚定的冻结行还在,裁决照样成为替换 run 的输入)。
S1 之后要新增题目或改计分再开补充提交期,强制走 retract——新题的分数也必须经过一次可申诉
的公示,这是同一条规则的推论。

## 后果

- 程序正义闭环:学生申诉过的规则集合与 S2 使用的规则集合恒等,除非重新给出申诉机会。
- 发布断言相应分裂:live 数据漂移(冻结守卫被绕过)不再中止发布——冻结的 rows 就是管理员
  预告出去的官方结果,照发 + CRITICAL 告警,事后必要时 retract;只有快照**内部**损坏
  (rows 与自身 manifest 不符)才中止——那不是守约,是发布残次品。
