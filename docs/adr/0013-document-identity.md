# ADR 0013：网页文档声明自己属于谁，服务端在业务处理前核对

- 状态：**已接受**（2026-11-06）
- 相关：[ADR 0012](0012-rsc-data-mode.md)、[Web Release 协议](../architecture/web-release.md)、[浏览器公开面](../architecture/browser-surface.md)

## 背景

浏览器里所有标签页共用一个会话 cookie。标签页 A 按 A 的身份加载页面并填写内容；这时另一个标签页以 B 的身份登录，cookie 随之换成 B 的。此后 A 页面发出的每个请求，服务端都会按 B 来授权和执行，因为它只能看到 cookie，无法知道这个页面原本属于谁。

现有的会话恢复只能缓解，不能消除这个问题。其他标签页登录时会广播通知，A 页面重新读取 manifest，发现身份变了就冻结。但在通知送达之前已经发出的请求，以及正在等待重试的请求，仍然会以 B 的身份执行。服务端本应拒绝它们，可它缺少拒绝的依据。

## 决定

**网页文档在请求里声明它属于谁；服务端在业务 handler 运行之前比较这一声明和真实会话，不一致就拒绝。**

1. **身份键。** 使用 manifest 已经下发给页面的 `identity`：对租户和用户做摘要，同一个人在任何会话里都相同，不同的人一定不同，并且不暴露任何 id（`@qualy/auth-contract/identity-key`）。匿名文档的身份键是 `anonymous`。
2. **怎样传递。**
   - HTTP 请求放在 `x-qualy-identity` 请求头里。
   - 实时通道（WebSocket）在浏览器里发不了自定义头，所以放在连接 URL 的 `identity` 参数里，和协议版本、release 的传法一样。访问日志对这个参数脱敏。
3. **判定**（同一个函数，供 `Viewer`、`Authenticated`、登出、实时通道握手，以及后续的服务端渲染预检共同使用）：

   | 文档声明           | 实际会话                       | 结果                                                                                                                  |
   | ------------------ | ------------------------------ | --------------------------------------------------------------------------------------------------------------------- |
   | A                  | A，包括 A 换了新会话           | 放行                                                                                                                  |
   | A                  | 没有会话，或会话已过期、不可用 | 按现有规则返回 `AUTH_REQUIRED` 或 `SESSION_EXPIRED`，保留清除 cookie 的行为，进入会话恢复，同一个人重新登录后可以继续 |
   | A                  | 另一个人 B 的有效会话          | `IDENTITY_CHANGED`（409）：页面冻结，不重放请求                                                                       |
   | anonymous          | 匿名                           | 放行；要求登录的接口照原规则拒绝                                                                                      |
   | anonymous          | B 的有效会话                   | `IDENTITY_CHANGED`                                                                                                    |
   | 网页请求没有带声明 | 任意                           | `IDENTITY_UNASSERTED`（409）：这是客户端违反了协议，不是换了人。交给平台恢复，进入 reload-required                    |

   "网页请求"指带有 `x-qualy-client-protocol` 头的请求。

4. **例外。**
   - 两个身份探测接口不做比较：`app.getManifest` 和 `auth.getSession`，它们在 endpoint 上带有 `IdentityProbe` 注解。它们回答的正是"现在是谁"，页面拿这个答案做恢复判断，但不能直接用它替换自己所属的身份。
   - 建立身份的接口（登录、外部登录回调）不挂这两个中间件。
   - 首次文档导航、静态资源和非网页客户端，都按现有政策处理。
5. **登出**会比较声明：会话已经不存在时照样成功；会话属于另一个人时拒绝，防止旧页面把别人登出。
6. **客户端。**
   - 文档身份由一个持有者保存，只在两种情况下改变：页面采用 manifest 时，以及页面明确切换身份时。
   - 拿到第一个可信的 manifest 之前，它处于"未初始化"状态，此时只发探测请求。
   - 每个逻辑请求在开始时固定自己的声明。会话恢复后的重放沿用这个固定值，绝不改用新身份。
7. **协议版本。** 客户端协议升到 5，服务端兼容窗口改为 5..5。部署后，旧标签页在下一次请求时进入现有的 reload-required，由用户决定何时刷新，不自动刷新。这次升级是因为引入了新协议，并不意味着每次普通部署都要升级协议版本。

身份键只用于一致性比较，不替代认证、租户和权限检查。每个请求仍然按它自己的会话授权。

## 代价

- 部署这一版时，所有已打开的旧标签页都要刷新一次。
- 匿名可读的 `Viewer` 接口，对一个声明了身份、但会话已经失效的文档，不再按匿名身份作答，而是要求先恢复会话。
- 实时通道的拒绝必须在建立订阅之前完成；拒绝原因通过关闭码告知。
