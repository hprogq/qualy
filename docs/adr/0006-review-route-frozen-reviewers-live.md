# ADR 0006:审核路线冻结,普通审核人实时解析

- 状态:**已接受**(2026-08-08)
- 领域:综合素质测评(docs/assessment-design.md §7 ADR-3、§14)

## 背景

一个批次持续数周。期间班长换届、学生转专业、组织结构调整。两种极端做法都错:把审核人固化成
user id,换届后旧班长仍收着一堆待审;每次都从实时组织树重新推导,历史批次的路线会随现在的
组织结构漂移。

## 决定

**结构冻结,身份实时。**

- 每个参与者在批次内有唯一冻结的 `assessmentAnchor`(+ anchor_path 快照)。
- 提交条目时快照**有效审核链**:哪些 stage、锚在哪些节点、quorum、normalTerminal、
  被跳过的 stage 及原因。这是结构,永久不变。
- **single/any 节点不保存具体审核人 user id**。收件箱是拉模型:按「当前 stage 的角色@节点 ×
  我的 RBAC 授予」实时 join。班长换届 → 旧班长收件箱即时清空、新班长即时可见,**零任务迁移**。
- 只有 `all` / `atLeast(n)` 计票节点在**进入时**快照 voter set(稳定分母);已投的票永久有效。
- 「找到学生 A 的班长」永远意味着「从 A 在**本批次冻结的锚点**出发,向上找到最近的班级型节点,
  取该节点上持有班长角色的人」——不是全树搜索,也不是看 A 现在的实时归属。

## 后果

- 换届不需要任何数据迁移动作,这是本决定最实际的收益。
- 计票节点是唯一需要快照身份的地方,因为「3 人中 2 人同意」在分母会变的情况下无意义。
- 锚点变更只影响此后新提交条目的路由;在途条目保持已快照的链。
