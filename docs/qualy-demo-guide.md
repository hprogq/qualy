# Qualy 面试演示指南

这条路线先用学生提交与班级审核说明项目解决什么问题，再展示复杂处理、成绩来源以及管理员的配置能力。演示者手动切换五个身份，不向访客公开账号或密码。

2026-10-08 已在新基线恢复的本地副本上登录五个身份，完成学生提交与班级审核通过，核对辅导员三轮修订及补件答复、负责人六学期导入依据与重新认定表单、管理员公式共享和两院组织结构。下文“预期”描述从干净基线开始时的演示结果，已经处理过的副本需要恢复后再演练。公网部署、CAS、GitHub、OIDC 与真实邮件尚未验证。数据范围、私有配置及完整验收结果见[演示数据说明](notes/demo-data.md)。

## 演示前准备

用独立预览副本完整演练一次，模板库保持不变。初次预览或重新开始演练恢复快照，想继续上次操作才使用 `--keep`。恢复会清掉预览中的操作，不在面试中临时执行，也不重建开发库。

只在本机记录下列四个入口，不将真实学号、密码或具体人员资料写进本指南：

| 本机记录 | 选择方法                                                                   | 用途                             |
| -------- | -------------------------------------------------------------------------- | -------------------------------- |
| 主线活动 | `student` 的第六学期“校园文化活动”草稿                                     | 现场提交，再由 `class-lead` 审核 |
| 多轮材料 | `counsellor` 待审中至少两次修订的材料                                      | 展开材料版本、退回原因及重新提交 |
| 补件回件 | `counsellor` 补件已答复的记录                                              | 比较原材料、补件要求与新附件     |
| 推免纠错 | `student` 推免竞赛中由个人改为团队的重新认定，以及另一人的品德文体导入更正 | 解释流程复核、重新认定与行政更正 |

预检时确认：

- 默认登录为 `student`，进入第六学期；第六学期和推免均显示进行中。
- 上表的材料能打开，窗口尺寸适合展示，列表搜索与筛选能找到预选案例。
- `student` 与 `class-lead` 同班，主线草稿提交后会落到该班的审核范围。
- 五个账号的本地密码已私下准备。不要设置 `QUALY_DEMO_ACCOUNTS`，不要把密码放到讲解画面中。
- 尚未部署外部认证时，从邮箱密码登录开始；已真实完成 CAS 配置后，可以用它作为学生的首次登录入口。
- 演示邮件前，另行验证邮件提供方、站点回跳地址和接收邮箱。数据里有邮箱不能证明邮件已送达。

账号依次为 `student@<邮箱域>`、`class-lead@<邮箱域>`、`counsellor@<邮箱域>`、`lead@<邮箱域>`、`admin@<邮箱域>`；`<邮箱域>` 是与当前基线匹配的 `QUALY_DEMO_EMAIL_DOMAIN`。仅改变配置不会修改已有账号。

## 8 至 10 分钟主线

### 1. 学生提交，约 1 分 30 秒

点击：**测评 → 2025-2026-2 软件学院 2023 级本科生综合素质考核 → 我的申报**。

先用十秒扫过草稿、待补充、审核中等不同状态，再打开预先选好的校园文化活动草稿。通过“继续填写”查看表单，展示填写内容与附件，点击“保存并提交审核”，在确认框点击“保存并提交”。记录该条活动名，下一账号用它查找。

预期：草稿进入审核中，处理记录增加本次提交。只提交这一条，其他补件和申诉保留作为后续讲解的材料。

可以这样说：

> 我从学生实际使用的流程开始。学生按学院配置的项目提交证明，系统会把这条申报交给当前有权处理的人。这里也能看到哪些材料还需要我补充，以及每次处理为什么发生。

若被追问实现：项目表单、计分配置和审核路线来自批次配置；材料有版本和访问权限，提交接口重新检查参评资格、当前阶段和对象状态。页面按钮与服务端守卫共同反映可执行动作。

### 2. 班级负责人审核，约 1 分 30 秒

点击：**右上角账号菜单 → 退出登录 → 登录 `class-lead` → 同一第六学期 → 审核工作**。

按主线活动名或本机记录的人物名称找到刚提交的材料，打开附件，点击“通过”，核对认定内容后确认。等五秒撤回窗口结束并确认提交成功，再切换身份。随后可在另一条已有补件往返的材料中点击“查看完整记录”，说明同一个列表里也有需要进一步核实的材料。

预期：这条校园文化活动的正常路线只有班级审核一步，通过后形成认定。第六学期竞赛项目另有辅导员确认步骤，不要将两个项目的路线混讲。不要为了展示复杂流程给已齐全的材料随意提出补件。

可以这样说：

> 班级负责人仍然是参评学生。他可以处理本班范围内的材料，同时也有自己的申报。系统会避开本人审核自己的情况；如果材料不足，可以提出具体补件要求，原记录会一直保留。

这条主线活动可以在班级环节完成。后面辅导员展示的是预先准备好的复杂案例，不承诺每个项目都必须经过全部五个账号。

### 3. 辅导员处理复杂材料，约 2 分钟

退出并登录 `counsellor`，进入**第六学期 → 审核工作**，切换到**按时间**，先展示不同来历的待办。打开预检选好的多轮材料，通过“查看完整记录”按时间顺序展示一次退回、修订后的材料及当前停留位置。再打开一条补件已答复的记录，比较补件要求与新附件。

然后切换到**2027 届软件学院推免 → 行政认定 → 导入记录**，打开品德与文体均值的导入，查看误用往年均值的那条旧认定；回到“认定记录”，按同一人搜索，打开后来更正的认定。该更正故事在推免批次。主线只看已完成的更正，不再现场重复导入大量数据。

预期：列表中既有新提交，也有已处理过的材料；补件回来的内容能解释它为什么再次进入待办，行政更正保留先前依据。

审核工作默认按项目聚合。单个项目的待办少是正常状态，不要把默认首组当作全部收件箱。推免可切到按时间查看混合队列，再切到成绩单或思想品德考核表，对比同类材料的不同处理过程。

可以这样说：

> 审核过程里，问题通常不只是通过或退回。这里能看到材料经过几轮修改，以及每轮解决了什么。学院统一导入的成绩也是认定记录，发现问题之后要留下更正过程，不能让旧数据无声消失。

若被追问实现：学生申报修订、审核轮、补件与认定分别保留历史。审核中的上提、学生申诉和工作人员复查有不同发起条件；复核链中间环节传递意见，最终环节才形成新的权威认定。

### 4. 负责人说明推免来源和纠错，约 1 分 30 秒

退出并登录 `lead`，进入**测评 → 2027 届软件学院推荐免试研究生综合评价**。

先到**行政认定 → 导入记录**，打开品德与文体均值的导入详情，在认定依据中指出六个来源学期、第六学期仍进行中，以及取数日期。再到**参评名单 → `student` 对应人物 → 申报 → 竞赛项目 → 预选材料**，在“审核记录”中看由个人获奖更正为团队获奖的历史。材料详情底部的“重新认定”可以打开认定内容与理由表单，主线查看后取消。

主线不必现场改变一个新分值。只有扩展演示时，才根据预先核实的纠错依据执行一次重新认定。

可以这样说：

> 推免这里用的是导入时六个学期的阶段性认定成绩。第六学期后来有变化，不会悄悄改掉推免记录，工作人员要核对后显式更正。直接重新认定又是另一种权限，我这个账号是经过明确任命才具备它。

若被追问实现：导入保存当时的来源依据与值，不存在隐含的跨批次自动依赖。重新认定在既有结论上追加新认定和原因；若有在途复核，界面会告知它将被终止，历史仍然保留。

### 5. 管理员展示配置能力，约 2 分钟

退出并登录 `admin`，依次点击：

1. **组织与权限 → 组织架构**：展开旅顺校区的软件学院，再展开英语学院的专业方向和直接挂班级的分支。
2. **测评 → 第六学期或推免 → 参评名单 / 人员权限**：各选一项组织归属变化、授权变化，只展开差异并解释处理方式。
3. **资源库 → 公式模板**：点击学校作者共享来的公式名称，查看作者、发布版本、参数和测试例。返回资源库的平级入口**计分公式**，打开管理员自己的“志愿服务时长折算”，进入**版本 → 发布版本**，点击该版本的分享图标，查看“已共享给”中的学校范围。已共享版本的图标提示为“已共享至 1 个单位”。

预期：能看到两个学院不同的层级与工作人员；名单、权限和项目配置的提示各自解释其问题。共享来的内容在“公式模板”页阅读，自己的公式在“计分公式”页维护，后者的发布版本中可以查看共享范围。

可以这样说：

> 不同学院可以使用不同的组织层级、项目和审核职责。组织变动以后，历史批次保留原来的事实，当前名单和授权按各自规则处理。公式则把一条认定转换成分值，发布后按版本使用，也可以共享给其他范围的规则维护人员。

讲到这里结束即可。接口、插件、事务和沙箱等实现细节留给面试官追问，不继续逐页浏览全部配置。

## 约 20 分钟扩展路线

沿用主线账号顺序，在对应账号停留时加入以下内容，减少反复登录。总时长按面试官兴趣取舍。

| 时段        | 身份与页面                                     | 具体展示                                                                         | 讲解重点                                           |
| ----------- | ---------------------------------------------- | -------------------------------------------------------------------------------- | -------------------------------------------------- |
| 0:00–3:00   | `student`，第六学期我的申报、我的成绩          | 提交主线草稿；打开一条待补件；展开旧学期一条完成的申诉                           | 当前动作与历史事实可追溯；归档批次用于阅读历史     |
| 3:00–6:00   | `class-lead`，审核工作、自己的申报             | 审核主线；对一条确有缺项的备用材料提出补件；查看自己被另一负责人审核的记录       | 范围授权、自审回避、具体补件要求                   |
| 6:00–10:00  | `counsellor`，第六学期与推免审核工作、行政认定 | 对比多轮修订与补件答复；区分申诉、上提和工作人员复查；看一次导入更正             | 同样的待审状态可以有不同来历；认定与材料处理分开   |
| 10:00–14:00 | `lead`，推免行政认定、参评名单、阶段安排       | 看六学期来源与取数日期；在备用案例上执行有依据的重新认定；看当前阶段开放哪些动作 | 明确授权、显式纠错、阶段只限制可操作时机           |
| 14:00–18:00 | `admin`，组织架构、名单、人员权限、项目配置    | 展开转班或转专业对账；新增/撤销授权差异；查看缺少审核落点的项目                  | 当前组织、批次归属和过去合法操作分别保留           |
| 18:00–20:00 | `admin`，资源库的公式模板、计分公式            | 在模板详情查看作者、版本、参数和测试例，再看自己公式发布版本的共享范围           | 单条计分可配置且可验证；旧引用不会被新草稿静默改写 |

班级负责人现场提出的新补件需要学生再次登录才能答复。20 分钟路线可以用另一条已经答复的案例展示后半段；如果面试官希望看完整往返，再增加一次学生登录，上传事先准备好的对应材料。

同样，执行过重新认定的备用案例已改变状态。下一次演练使用另一条案例或恢复预览副本，不把同一条记录当作可以无限重复的演示按钮。

## 追问时可展开的几个例子

### 转班和转专业

在管理员的参评名单打开组织差异，比较本批次归属与当前组织。解释“同步所选”和“保留本批次归属”的区别。跨学院变化还需要检查对新范围的管理权限。

普通学期中的换班、留级、复学由固定配角承载，主角身份保持稳定。不要为了即时演示移动主线学生，导致后续班级负责人找不到材料。

### 授权变更

打开人员权限，展示一项组织侧新增权限待接纳，以及撤销后已失效的权限。说明角色授予的是职责与范围，用户类型只是身份和站位约束。

主 `lead` 本来就有校级成绩读取职责。用它演示本院审核和管理范围即可，不能宣称它无法看到其他学院任何成绩。系统管理员能修改认定也来自显式督查任命，不是所有业务权限的隐式绕过。

### 审核链缺口

项目配置里“无法申报”表示某些参评人的审核路线找不到所需落点；“无人可审”是已进入流程的材料缺少适格审核人。分别选择对应案例，展示原因与下一步，不混为一类问题。

在面试副本上变更角色或路线会影响后续工作，8 至 10 分钟路线只展开详情；需要执行时先确认备用案例及受影响范围。

### 邮件与外部登录

邮件是可选补充演示，建议使用 `counsellor@<邮箱域>` 的邮箱验证流程：由演示者本人点击**我的 → 账号安全 → 邮箱 → 发送验证邮件**，切到自己控制的收件端，打开真实收到的邮件并完成确认。该按钮只在已有邮箱且尚未验证时显示；演练前核对状态。只有实际投递、收件和回跳都成功，才展示这一步。

本轮数据生成与文档验收不发送真实邮件，不伪造收件记录。若尚未完成邮件配置，跳过这一项，不用截图冒充实时收件。自动代理也不得因这份指南存在就擅自发送邮件。

CAS 的两个私有学号分别匹配 `student`、`class-lead`。GitHub、OIDC、CAS 的提供方、密钥、回调与外部身份绑定属于后续部署配置，seed 不创建。当前未验证的方式不出现在现场承诺中。完整恢复演示数据库会丢失基线生成后新增的外部提供方、密钥和身份绑定；恢复后重新配置、绑定并验证成功，才能再次演示外部登录。

## 哪些页面不必强行展示

| 情况                           | 原因                                 | 演示选择                                             |
| ------------------------------ | ------------------------------------ | ---------------------------------------------------- |
| 管理员没有普通审核待办         | 没有给它编造学生或辅导员职责         | 展示组织、权限、配置和显式督查能力                   |
| 辅导员与负责人没有我的申报     | 教职工未加入学生参评名单             | 展示审核、行政认定或批次管理                         |
| 中山校区没有虚构学院和学生     | 私有素材没有提供可靠的具体归属       | 只说明可配置校区层级，不强行展开                     |
| 归档学期没有写入入口           | 历史应保留，现场操作在进行中批次完成 | 选一条历史讲明白即可                                 |
| 推免材料审核阶段不能新建或重交 | 该阶段已经关闭对应动作               | 新建、修改演示放在第六学期，推免展示审核、补件和复核 |

## 讲解的准确边界

- 展示的是虚构业务实例，学校名称真实不等于已经被学校正式采用。
- 公式目前处理单条认定。项目累加、取最高和计分组上限按各自实际配置解释，不宣称公式级跨申报封顶或加权汇总已经实现。
- 阶段名称中出现公示，不等于已经形成正式的不可变公示快照。未具备完整可演示入口的能力不作为主线承诺。
- 推免取数是导入时的阶段性成绩；后续显式更正有历史，不是跨批次实时自动同步。
- 源码、定向测试、完整种子验收、浏览器操作和生产部署是不同证据。完成哪一层就说到哪一层。

## 演练后的恢复

退出所有演示账号，停止这份预览进程。下一次从通过验收的快照恢复预览副本，数据库与附件同时恢复。模板库和基线包保留为生成时的状态，避免把上次演练的处理结果覆盖回去。

外部登录配置与邮箱验证状态在完整恢复后回到基线，基线生成后的配置、绑定和验证结果会丢失。恢复前准备重配步骤，恢复后重新完成配置、身份绑定及实际邮箱验证。生产或公网演示站的恢复按[部署流程](../deploy/demo/README.md)单独执行，不把本地预览操作当成生产更新。
