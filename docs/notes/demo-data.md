2026-10-08 已完成独立演示库生成、数据验收、私有快照导出与副本恢复。生成器及检查代码提交为 `327fdd005`，具体范围见文末验收记录。公网演示站、外部登录与真实邮件尚未部署或验证。

组织规则支持学校、校区、学院、年级、专业、专业方向、班级及部门。班级可以直接在专业下，也可以在专业方向下。英语学院部分班级使用方向节点，其名称属于演示配置，不代表学校现行培养方案。

## 素材与身份边界

本次私有素材由作者授权从 `/Users/hangqi/Downloads/seed` 读取，包含人员目录、教务账号结构、综测结果、证明材料与推免资料。原始文件及账户明细不进入仓库。

- [统计编译器](../../tools/demo/compile.ts)与[统计库](../../tools/demo/library.json)提供班级规模、成绩分布、活动频率和人员变动的参考。
- [活动目录](../../tools/demo/catalog.ts)和[虚构姓名生成器](../../tools/demo/seed/names.ts)生成公开场景。不得直接复用原始人员姓名、联系方式、证件号码或完整真实账号。
- 教务账号素材中的学院、教务职能账号用于提炼无学工号的业务账号形态。原系统的“系统管理”类型不等于 Qualy 的系统超级管理员；原表的一卡通字段为空，也不能作为学工号缺失的判断依据。
- 无学工号背景账号包括校级规则维护、两院教务办公室。其用户类型为普通业务账号，权限经角色授予，不使用受保护的系统账户类型。
- 邮箱域由 `QUALY_DEMO_EMAIL_DOMAIN` 提供，生成、校验、预览、E2E 与基线恢复使用同一配置，独立于网站公开地址和邮件发件人。只有实际邮件提供方与收件服务验证后，才能宣称邮件可送达；生成器本身不发送真实邮件。
- [材料模板](../../tools/demo/pictures.ts)生成带演示标识的虚构证明。日期、获奖级别、名次、个人或团体属性应与申报对应；补件答复必须解决所请求的问题，不能重新上传原件假装补齐。跨学期使用的通用证明不写固定年份，有具体日期或补件事实的重点案例使用对应材料。

私有标识由 [private-identity.ts](../../tools/demo/seed/private-identity.ts)读取，缺少、重复或无效时拒绝生成，错误不输出实际值。两项配置为：

- `QUALY_DEMO_STUDENT_BUSINESS_NO`
- `QUALY_DEMO_CLASS_LEAD_BUSINESS_NO`

本机可以将它们放在已忽略的 `data/demo-private.env`，权限设为 `0600`。文件同时可以提供本次生成需要的演示库、存储目录和密码变量。具体号码不写入代码、测试、文档或提交消息，也不从其中推导其他学生号码。生成出来的数据库及其 dump 会包含这两个标识，同样属于私有产物，不作为公开代码附件发布。

## 五个主要登录身份

| 身份       | 邮箱                  | 业务内容                                                   |
| ---------- | --------------------- | ---------------------------------------------------------- |
| 系统管理员 | `admin@<邮箱域>`      | 组织、角色、批次管理、公式与共享；显式督查任命后的重新认定 |
| 学生       | `student@<邮箱域>`    | 自己的六学期与推免申报、补件、申诉和成绩                   |
| 班级负责人 | `class-lead@<邮箱域>` | 自己的申报、本班审核与自审回避                             |
| 辅导员     | `counsellor@<邮箱域>` | 审核工作、补件往返、复查、行政认定与导入纠错               |
| 综测负责人 | `lead@<邮箱域>`       | 复杂复核、批次管理、计分规则与显式授权的重新认定           |

表中的 `<邮箱域>` 指上述环境变量。配置需要与所选基线中的现有邮箱一致；预览启动前会核对五个账号，域名不匹配时停止。
修改环境变量不会重命名已有用户，也不会改写归档。已有数据换域须单独审阅并定向更新邮箱及相关验证状态，保留用户 ID、
密码和外部身份绑定；自定义格式 dump 应在隔离副本更新后重新导出，不对归档字节直接做字符串替换，也不需要重跑场景生成。

密码只由 `QUALY_DEMO_ADMIN_PASSWORD` 与 `QUALY_DEMO_PERSONA_PASSWORD` 在生成时提供；部署后的密码按部署配置管理。展示实例不设置 `QUALY_DEMO_ACCOUNTS`，不在登录页公开账号密码，也不冻结演示者所需的账号操作。

两个学生主角固定为同班，创建时使用独立的 `demo-student` 类型。其他学生仍使用普通 `student` 类型，参与业务但不加入任何已配置登录入口的 allow-list。当前生成器将已有入口限制为系统账户、演示学生和教职工；其余背景人物没有生成可用的本地登录绑定。

GitHub、OIDC、CAS 由后续部署配置，seed 不创建这三种提供方或密钥。学校 CAS 分别通过两项私有学号匹配 `student` 和 `class-lead`；新增入口仍须设置受众，排除普通学生。外部身份绑定、邮箱验证与邮件收件只能由真实操作形成，不伪造成功记录。

## 故事与随机化

生成器通过产品服务创建人物、组织、角色、申报、认定和处理历史，不直接拼装合法性未知的业务状态。历史时间由[时间线工具](../../tools/demo/timeline.ts)在受控的演示库中放置。运行时禁用会与播种竞争的调度循环；公式发布和计分使用实际沙箱。

[独立随机流](../../tools/demo/seed/random-stream.ts)按学期、人物、项目等稳定要素抽样。人物参与度、学业表现和持续经历有联系，不因一次界面刷新重新随机。主角与重点案例是稳定入口，背景人物提供不同活动、材料、提交次数和处理间隔。

第六学期使用[当前案例计划](../../tools/demo/seed/term-scenes.ts)：草稿、首次提交、一次重交、多次重交、待补件、补件已答复、提请复核、申诉、工作人员复查和退回待修改。队列停在约定时刻，尚未发生的后续操作不会为了完成种子而全部执行。

推免使用[辅导员案例计划](../../tools/demo/seed/selection-scenes.ts)：首次材料、修改后重交、多轮修订、待补件、补件回到收件箱、申诉、复查和上提。资格材料的差异对应可见的问题，例如缺签字、缺盖章页、报告被截断或填报分数与报告不符。

同一项目仍遵守统一审核制度。不同经历来自证据问题、分支、轮次与停留环节，不随机打乱合法流程。两名主角不参加会破坏现场演示路径的转班或退学故事；这些变化由固定配角承担。

## 推免成绩与权限口径

推免的品德与文体均值取六学期在导入时的阶段性认定成绩。前五学期已经归档，第六学期仍进行中，来源必须显式包含六个学期，不能仅查询归档批次。

导入依据记录来源学期及取数时点。第六学期之后的认定变化不会自动改写推免记录；工作人员核对后，通过可追溯的更正操作处理。缺少某学期的来源属于待处理的数据问题，不能静默改用五学期均值。短生成只用于开发定位，不能作为满足六学期口径的面试基线。

重新认定遵守[领域设计 §32.87](../assessment-design.md)：系统管理员不天然拥有此权限。本数据集给 `lead`、`admin` 明确授予综测督查角色，按学院限定范围；普通审核角色不会由此获得流程外纠错权。

主 `lead` 保留校级成绩读取职责，不能用该账号证明“完全看不到另一学院成绩”。可以演示的是不同学院的审核与管理范围，以及具体权限与身份分开配置。第二学院负责人和校级公式作者使用仅含公式编写权限的独立角色，不因编写公式获得校级成绩读取权。

推免思想品德考核表沿用当前演示链：班级负责人初审，争议进入班级合议、辅导员、学院工作组。是否在真实学校制度中让学生干部处理这种材料，仍是独立政策问题；演示不将该链宣称为学校正式规定。主线的班级审核选用第六学期活动材料。

## 公式展示边界

展示单条认定如何映射为分值，例如竞赛级别与名次、科研成果类别、志愿时长折算。管理员有自有公式和草稿；校级作者共享到学校范围，使管理员的公式共享列表有真实可见来源。

现行中文界面中，共享来的已发布公式入口叫“资源库 → 公式模板”，其详情展示作者、版本、参数和测试例；自己的公式入口叫“资源库 → 计分公式”。自有公式的“版本 → 发布版本”列表中，分享图标用于查看或管理共享范围。两个页面是平级入口，模板详情不是原作者公式的编辑页面。

公式不遍历同题所有申报。项目的累加、取最高和计分组上限属于各自的配置能力，不能讲成公式级跨申报封顶或加权汇总。新数据不使用“封顶累加”“加权合计”作为公式示例名称。

## 生成、检查与预览

以下是后续重新生成与检查的操作入口。生成目标必须是空的独立演示库；数据库重建是单独的明确操作，不用开发库验证。

在私有环境文件提供目标与凭据之后，用 Node 在启动前加载配置，避免把标识或密码写入命令文本：

```sh
mise exec -- node --env-file-if-exists=.env --env-file=data/demo-private.env tools/demo/seed.ts
mise exec -- node --env-file-if-exists=.env --env-file=data/demo-private.env tools/demo/check.ts
mise exec -- node --env-file-if-exists=.env --env-file=data/demo-private.env tools/demo/snapshot.ts
```

生成、检查使用相同的 `--stage` 与 `--migration-state` 参数。默认完整生成保留第六学期和推免进行中；`QUALY_DEMO_TERMS` 和 `QUALY_DEMO_EPISODES` 是开发用的缩短方式，不能把缺少历史的快速结果当成正式演示基线。

快照同时包含数据库和引用的附件。`demo:snapshot` 检查附件对应关系，并拒绝会话、待确认邮件或本机密钥加密数据混入基线。仅支持本机 5434 端口对应的演示容器，数据库目标与产物权限约束见[部署流程](../../deploy/demo/README.md)。`--clear-runtime` 会删除运行态数据，只有确认目标是可清理的演示副本时才使用。

完成验收并生成快照后，加载同一私有环境文件运行 `tools/demo/preview.ts`，将其恢复到 `qualy_demo_preview`，附件放到 `data/demo-preview/storage`；`--keep` 继续上次预览。现场操作只写预览副本。恢复演练环境时，不覆盖生成模板库，不从演练后的数据库重新制作默认基线。预览读取 `QUALY_DEMO_SNAPSHOT_ROOT`，应与本次快照输出目录一致；不提供时使用默认目录。

## 新基线验收

源码检查、数据库检查、界面走查和生产验证分别记录，不相互代替。重新生成或更新基线时，按以下要求核实内容；本次实际结果见下一节：

1. 前五学期归档，第六学期和推免进行中；两个学院的范围、人数与工作人员正确。
2. 五个身份逐批次检查有职责的页面，能定位重点案例并继续执行下一步；辅导员与管理员不被为了填空加入学生参评名单。
3. 逐页收件箱覆盖首次、多轮、补件、申诉与复查；不能只满足某个类别全库数量大于零。
4. 材料、时间、改动说明与处理决定一致；没有与原件相同的补件答复、无主的在途轮或失效却仍可操作的权限。
5. 六学期来源完整，推免保存导入时成绩；更正保留依据和历史。
6. 公式自有与共享列表可见，范围正确，示例名称不暗示未实现能力。
7. 普通学生不在登录入口受众中，两个学生主角可登录且被纳入批次；私有标识、密码不进入 Git。
8. 附件快照与数据库引用相符，预览从快照恢复后仍能打开材料。
9. 按[面试演示指南](../qualy-demo-guide.md)实际走完一次，再将实际验证日期、源码提交和检查结论简短补充于此。不要追加完整终端输出。

## 2026-10-08 验收记录

本次完整生成在本机 5434 端口的独立演示库执行，共 9 个批次、1,215 个用户。软件学院前五学期归档，第六学期有 984 名参评人且进行中；推免有 72 名参评人且进行中。英语学院两个批次各 180 人，一个归档，一个进行中。

完整生成后发现背景活动抽样会在同人、同项目、同学期产生重复申报。生成器已改为无放回抽样，并区分同名科研项目与软件著作权。现有基线的 87 条多余申报通过正常产品流程更正和作废，原历史保留；临时重开的归档批次已经恢复归档。没有绕过业务服务直接修改申报或认定状态。最终基线通过最新完整检查，但未再次从空库运行约 100 分钟的完整生成；抽样修复另有定向回归测试。

验证结果：

- `mise exec -- pnpm exec vitest run tools/demo/tests`：17 个文件、126 项测试通过。
- `pnpm typecheck` 通过；最终源文件补充检查 `pnpm exec tsc --noEmit` 通过。

- 独立读取 72 人的六学期成绩，共 432 次产品成绩查询，全部符合六学期均值及阶段性来源口径；导入撤销和显式更正存在。

浏览器在恢复出来的副本上成功登录五个账号，完成学生草稿提交、班级负责人审核通过，核对辅导员三轮修订和补件答复、负责人六学期导入依据及重新认定表单、管理员自有与共享公式及两院组织结构。重新认定表单仅打开后取消，未另行改分。演练操作只改变副本，作为下次起点的基线没有包含这次现场提交。详细操作入口见[面试演示指南](../qualy-demo-guide.md)。本轮未发送真实邮件，也未验证学校 CAS、GitHub 或 OIDC 登录。
