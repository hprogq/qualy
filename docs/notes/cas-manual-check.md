# CAS 人工联调清单

自动化只依赖仓库里的假 CAS(`auth/tests/effect-cas.test.ts`)。真实学校的 CAS 由人按本清单联调一次,**不进 CI,
任何真实值(账号、学号、姓名、单位、ticket、服务器原始答复)都不写进仓库**——需要留证据时只记「通过 / 不通过」与现象。

## 准备

1. `.env` 里不设 `QUALY_PUBLIC_URL`(开发缺省 `http://localhost:5173`),`pnpm dev` 起开发环境;学校 CAS 在内网时
   把它的主机名或网段写进 `QUALY_AUTH_PRIVATE_PROVIDER_ALLOWLIST`。
2. 目录里要有一个人员编号与自己 CAS 账号对应的人(`目录导入` 或手工建),其身份类型在该入口的受众里。
3. 管理端「登录方式」新增一个 CAS 入口,地址标识随意(如 `campus`),记下详情页给出的回调地址。

## 步骤

| #   | 操作                                                                            | 期望                                                                 |
| --- | ------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 1   | 服务地址填 `https://<学校 CAS 域名>/cas`,协议 CAS 3.0,人员编号取「登录名」,保存 | 入口显示已就绪,可启用                                                |
| 2   | 启用;打开登录页,点该入口                                                        | 跳到学校 CAS 登录页,地址栏 `service=` 是回调地址加 `?flow=`          |
| 3   | 用自己的账号登录                                                                | 回到 Qualy 首页且已登录;`sign_in_events` 里有一条成功                |
| 4   | 浏览器后退到 CAS 回跳地址再打开一次                                             | 回到登录页并提示本次登录已过期或已完成                               |
| 5   | 把人员编号来源改为「服务器返回的属性」,填学校返回的编号属性名,再登录            | 仍能登录;属性名写错时提示没有对应账号                                |
| 6   | 把协议改为「自定义」,校验地址改为 `/proxyValidate`、请求方式 POST,再登录        | 仍能登录                                                             |
| 7   | 高级设置勾选「每次都要求重新输入密码」,再登录                                   | CAS 不再直接放行已有会话,要求输入密码                                |
| 8   | 在目录里停用自己,再登录                                                         | 回到登录页提示没有对应账号;`sign_in_events` 的原因是 `user-disabled` |
| 9   | 服务地址改成一个不可达的地址,再登录                                             | 提示暂时无法连接统一身份认证                                         |

## 不在本清单

CAS 登出与 SLO、代理票据(PGT/PT)、`checkAliveTicket`、自动建号——本产品当前都不做。
